# 阅读与作品维护

## 已上线的能力

- `/picks/`：近七天的规则阅读候选，每次最多五条，不按配图或虚构热度排序。
- `/topics/`：三个持续专题，连接已发布的正式文章、资讯分类与可用作品。
- `/lab/`：真实新闻站与流式呈现实验。实验使用预设内容，不作为模型性能测试。
- `/search/`：文章全文及全部资讯标题、摘要、中英原文、来源的统一检索，先筛选后每页三十条。
- `/subscribe/`：正式文章、阅读候选、逐条资讯三个 RSS。示例稿不进入正式文章 RSS。
- `/news/story/:id/`：稳定的独立资讯阅读地址，不依赖分页位置，避免 RSS 与收藏因新增新闻改变。

## 作者精选

编辑 `src/config/editor-picks.json`，目前为空。条目格式：

```json
{"id":"存在的新闻 ID","reason":"你确认后的推荐理由","confirmed":true}
```

只有作者已确认、ID 存在、推荐理由非空的记录可进入作者精选。不要让自动流程把 confirmed 设为 true；不要把 AI 点评写成作者实际经历。新增数据仍通过 GitHub 提交与既有发布链路上线，无独立 CMS。

## 发现页：阅读与建立连接

`/discover/` 顶部用简短的个人介绍与 Focus 说明作者背景和当前方向，附「关于我」「关于站点」链接。其后以「最近在做」「一起做」「保持连接」承接实际项目与交流，下方的「值得关注」提供原始资料、行业作者和开发者社区。每项说明阅读价值并给出直接入口，不使用含义模糊的「阅读清单」，不声称推荐作者都是站长实际关注的人。

维护 `src/data/discover.json` 的 `profileIntro` 与 `focus` 可更新顶部介绍；只使用已确认的作者信息，Focus 链接必须对应真实项目或开放问题。资讯「精选」首页不再放个人介绍，与其他资讯分类共用 `NewsEdition` 的卡片、网格和阅读弹窗。

维护 `src/data/people.json`：

- `sites` 为「核心站点」，`sourceId` 必须对应 `src/config/news-sources.json` 中已有的订阅源。只在站内确有收录时显示「站内相关」，该入口是来源名检索，不是严格的来源筛选或实时条数。
- `authors` 为「行业作者 / 精选推荐」，以官网核实内容方向与链接，保留 `evidenceUrl` 与 `checkedAt`。当前为公开资料推荐，不表示用户关注记录、私人关系或作者背书。
- `communities` 为「找到同路人」，链接已有订阅源对应的公开社区，说明可参与的活动，不虚构成员身份。
- `provenance` 记录推荐与真实订阅的区别。没有真实关注记录时，不把推荐名单标成「我关注的人」。

作者与站点可直接阅读原文或查看公开作品；「推荐给我」只打开预填信息的 GitHub Issue 页面，由访问者决定是否提交。没有站内社区、账号或自动发帖。

## 内容状态

`demo: true` 是排版示例；`draft: true` 不生成生产页面，本地开发模式可通过文章地址预览。AI 辅助整理的实现记录应在正文与署名中说明依据。私人资料不要放进公开仓库的草稿。模板见 `docs/WRITING_TEMPLATES.md`。

## 后续内容与接入

本地收藏与已读的存储模块保留在 `src/scripts/reading-store.ts`，但当前页面未接入，且没有 `/reading/` 路由；它不是当前已上线的界面能力。

仍需作者提供或确认真实实测、个人观点与相关媒体。Clarity 仍需账号登录与项目绑定；本轮没有改变其账号状态。没有自动代发邮件，也没有邮件订阅后台。

## 运行保障

定时工作流已存在成功运行。发布流水线不取消正在保存历史的任务；所有来源失败、翻译失败或构建失败仍阻止部署。源状态与超过 36 小时未更新提示保留；GitHub Actions 页面提供具体失败步骤。未新增外部消息通知服务。

## 线上质检补充（2026-10-03）

首页与自动候选排除版本发布日志；这类信息仍可在完整资讯中查询。英文候选必须同时有可用中文标题与摘要。采集缓存与展示层均屏蔽明显的重复生成或异常膨胀译文，回退到原文并标明译文不可用；这项检查不能验证语义准确性，技术术语、数字仍应与原文核对。

`src/config/translation-edits.json` 保存当前首页三条英文候选的 AI 校译。覆盖仅在 ID、英文标题与英文摘要完全匹配时生效；来源更新后自动失效。校译仍标注 AI，不能当作作者确认或事实背书。
