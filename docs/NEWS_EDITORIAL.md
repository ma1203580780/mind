# 新闻日刊的来源与发布规则

## 阅读与归档

- `/mind/news/` 累计展示全部历史，每页 30 条；日期页按北京时间收录日归档。全站按原文 `publishedAt` 倒序；只有发布日期的旧记录按该日北京时间零点排序。不得把收录时间冒充原发布日期。
- 顶部分类：AI 资讯、一人公司、产品设计、审美提升、产品营销、AI 协作、经济观察。右侧日期与语言、分类组合筛选；先筛选全部历史，再分页。本页搜索只搜索当前页，界面明确标识。
- 旧的细分类数据保留，通过 `news-topics.mjs` 映射到阅读板块；旧分类 URL 继续可访问。手机新闻、笔记和博文列表维持双列。

## 实际采集

运行 `scripts/collect-news.py`，读取 `src/config/news-sources.json` 的公开 RSS / Atom。GitHub Actions 北京时间每天 08:17、14:17、20:17 计划采集。GitHub 调度可能延迟，不承诺整点即时刷新。

- 快讯默认只接收近 72 小时未收录内容。少量更新较慢的创业访谈、产品设计和营销源明确设置 `maxAgeHours:168`，只接收近 7 天内容，保留原发布日期。无日期、未来内容和时间窗外内容不收录。
- 同一日多次运行追加，整天最多 200 条；历史永不因分页或每日更新被覆盖、截断。规范链接和标题去重，跨日依据全站历史链接去重。
- 按当日已收录数量优先补充较少的板块，随后再按源限制收录。论文预印本每天最多 30 条，版本发布每天最多 12 条；正常来源默认最多 25 条，新增专业源通常 8–12 条。宁缺毋滥，不要求每个分类每天有新稿。
- 一人公司收录独立创业、小团队 SaaS 经营与创始人访谈，不把创业故事误称为全部由一个人完成。产品设计优先研究与实践；审美提升关注作品与创作；产品营销标注厂商研究的来源与立场。综合中文源按标题关键词筛选。
- 保留原始标题、最多 600 字符的 RSS 摘要、源链接、源发布时间、采集时间、feed URL、作者（源提供时）。自动采集不等于人工事实核验，不生成新闻、投资建议或没有出处的解读。论文、机构公告、版本发布、媒体、社区文章分别标注。
- 不复制整篇或付费正文，不绕过登录、反爬或付费墙。只用公开源；失败在信息源页公开，保留旧数据。所有源均失败时阻止新部署。

## 中英对照与图片

- `language=zh/en` 表示来源语言。英文译成中文之后仍属于英文对照，不冒充中文来源。原文随时可查看。
- `scripts/enrich-news.py` 使用校验过 SHA-256 的 Argos 英中 1.9 模型，在 GitHub CPU 本地运行，无翻译 API 密钥。译文按模型版本和文本哈希缓存，明确标注机器翻译。术语、数字及结论请核对原文。模型失败阻止新部署。
- 图片只取对应新闻的 feed、发布者页面 Open Graph、正文图或 arXiv 原始论文图。保留出处，剔除装饰 SVG、Logo、头像、赞助图、通用重复 Banner 和签名临时链接。原图失效退回文字卡，不使用无关占位图。
- 卡片标题、摘要、图片可打开详情；长文单列，中英桌面对照；支持 Escape、焦点返回与减少动态效果。

## 发布与验证

1. 修改前读取最新 main，避免覆盖并发采集结果；仅更新本次任务文件。
2. 运行 Python 新闻测试、`npm run test:news`、`npm run build`。校验阻止未来日期、错误分类、危险链接、重复与过期内容，不能替代事实核验。
3. 普通推送构建站点；提交含 `[collect-news]` 会同时触发一次真实采集、翻译和图片补充。定时与手动运行同样执行采集。
4. 合并历史、通过构建后提交数据，上传并部署 Pages。区分提交成功、构建成功、部署成功与线上核验，不把配置完成说成已采集成功。
5. `/news/sources/` 展示全部配置源及最近读取状态；响应 SHA-256 供追溯。最近成功采集超过 36 小时显示提示。

先前的每日 AI 编稿任务已停用；当前由 GitHub Actions 获取真实订阅内容，不依赖 ChatGPT 定时任务或付费模型。
