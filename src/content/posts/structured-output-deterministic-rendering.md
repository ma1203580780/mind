要模型回答 JSON、XML、LaTeX、Markdown，是一件排版上的事，不是一次能力上的扣税——这是直觉。2026 年 4 月的 [The Format Tax](https://arxiv.org/abs/2604.03616) 把这条直觉翻了过来：**结构化输出要求会显著拖低推理与写作表现**，而且**主要损失发生在提示词里：光是那句「请用 JSON 回答」，在解码器还没施加任何约束之前，就已经造成了大部分准确率下滑。**

这句话的位置很关键。它意味着问题不出在「格式没管严」，而出在「你让模型一边想内容一边管格式」。同一批作者给出的解法是**把推理和排版拆开**——先自由生成、再第二遍重排，或者在单次生成里给足思考空间：拆开之后，丢掉的大部分准确率被收回来了。

所以这篇文章只谈一个分工：模型只产出中间结构，格式由程序渲染。

## 模型同时做两件性质不同的决定

让模型直接吐最终成品，等于在一次生成里塞进两类决定：写什么，和长什么样。这两类决定的性质完全不同。

2026 年 8 月的 [SeaSlides](https://arxiv.org/abs/2608.03298) 把这件事写进了摘要第一句。它说已有系统各满足一半需求：**模板保住规整度，但限制适应性**；而**自由形式的 HTML 或 SVG 把灵活性给了模型，代价是让它去做低层次的渲染决定**。作者把这种错配称为 long technical decks 脆弱的根源，尤其是幻灯片里出现公式、代码和数据图的时候。

这两句话值得并排看。它们说明模板的僵硬和自由的脆弱不是两个独立的缺点，而是同一个错误的两种表现：**决定放的层级放错了。** 模板错在把「这一段该讲什么」也固定了；自由生成错在把「这块放哪里、多宽、怎么对齐」也交给了模型。

SeaSlides 给出的分界线是：模型不再写坐标、内联样式或原始 SVG 几何，而是**通过可复用组件和能力模块写结构化的幻灯片内容，由模板拥有布局、样式和渲染**。公式、代码、图表则被路由给专门的渲染器。

这条分界线一旦立起来，自由生成的问题就换了性质。它不是因为模型「画得不好」，而是因为格式与布局的执行会随元素数量和嵌套层数迅速放大——一份二十个元素的卡片用模型摆得八九不离十，一份两百个元素的文档就不是同一件事了。程序渲染没有这个斜率：第一块和第一万块的成本一样，结果也一样。

## 格式的成本是提示词成本，所以约束解码救不了

Format Tax 那篇论文里最值得记住的不是结论，而是它对原因的排查过程。研究界对结构化输出掉分的解释一直集中在约束解码上——把采样限制在合法 token 上会带来采样偏差。论文的判定是：**采样偏差只解释了退化的一小部分**，主导成本从提示词就进入了。

这个区分有直接的工程后果。如果损失主要来自解码器的 token 掩码，那方向就是换更好的解码器、更聪明的语法约束。但成本在提示词一侧，那么无论解码器多干净，那句格式要求本身就在消耗模型。于是「把 schema 写得更严格」不是解药，反而是在同一处继续加码。

论文的实验面相当宽：**六个开源权重模型、四个 API 模型、四种格式，任务覆盖数学、科学、逻辑与写作。** 拆开之后，丢掉的大部分准确率被收回。论文同时标注了一条边界：**多数近期闭源权重模型几乎没有格式税**，也就是说这不是结构化生成的固有代价，而是当前开源权重模型尚未补上的差距。

这条边界不该被略过，它决定了文章后续判断的适用范围。如果你用的是近期闭源模型，格式税这一项在你的账单上很小。但下面那部分不是。

## 大文档会静默卡住，这是容量问题

2026 年 4 月的另一篇论文 [When Agents Go Quiet](https://arxiv.org/abs/2604.16736) 描述的失败模式更刺眼：**LLM 驱动的编码 agent 在生成又大又重格式的文档时，会静默地返回空响应**——作者称之为 output stalling。它不报错，不降级，只是没有输出。

论文没有把这件事当成模型的脾气，而是当成容量问题。它引入 **Output Generation Capacity（OGC）**，衡量 agent 在当前上下文状态下实际能产出多少东西，并明确指出这个量**经验上小于原始上下文窗口**。上下文还有空间，不等于还能写。格式开销正好是吃掉这段差额的东西：token 花在括号、标签、样式属性上，就没有花在内容上。

论文的第二项贡献可以当作分工的理论依据：它证明了一条 **Format-Cost Separation Theorem**——**对任何格式开销乘子大于 1 的格式，延迟的模板渲染在 token 效率上永远不劣于直接生成。** 注意这个说法的强度：它不是「通常更好」，而是对一大类格式的条件性不劣。

实验部分给的是量级。跨 **三个模型（Claude 3.5 Sonnet、GPT-4o、Llama 3.1 70B）、四种文档类型**，并有逐组件消融：**延迟渲染把 LLM 生成 token 减少 48–72%，并且完全消除了 output stalling。**

把两组数字放在一起，分工的理由就不是审美问题了：一部分是省 token，另一部分是把一类静默失败从系统里删掉。

| 做法 | 模型要产出什么 | 生成 token | 格式一致性由谁负责 |
| --- | --- | --- | --- |
| 直接生成成品 | 内容加全部格式 | 基准 | 模型 |
| 分块生成后拼 | 内容加局部格式 | 介于两者之间 | 模型加拼接程序 |
| 延迟模板渲染 | 只有语义结构 | 减少 48–72% | 模板与渲染器 |

三行里第三行是论文证明过的那一行。

## 中间层必须留住语义，否则分工只是搬家

到这里有一个容易踩空的地方。把格式拿走，不等于把责任拿走。中间结构必须承载足够的语义，否则渲染器面对的是「第一段文字、第二段文字」，它仍然不知道该把哪一段当标题。把格式换成结构，但结构里没有语义，只是把错误从渲染阶段推到了下游。

SeaSlides 的组件化方案里有一个细节值得单独拎出来：公式、代码、图表**不是以文本形式塞进结构**，而是被**路由给专门的渲染器**。这个动作的前提是中间层能认出「这是一个公式」，而不是「这是一串长得像公式的字符」。识别得出来，才能路由得出去。

由此可以得到一层更基本的判断：**能渲染，和渲染出来是对的，是两件事。** 字段齐全、JSON 能解析、模板不报错，只证明结构合法。它不证明摘要没有歪曲原文，也不证明这一节该讲的东西讲全了。把格式交给程序，收益在于程序负责的那部分不再出错；模型负责的那部分——内容对不对、覆盖全不全——一点都没有被分担。

SeaSlides 那条约束在这里咬回来：模板保住规整度的代价是**限制适应性**。所以中间层不是越窄越好。窄到只剩位置信息，渲染稳定但内容没法分类；宽到允许自由 HTML，等于把渲染决定又还给了模型。可用的那条线，是让中间层只描述**语义角色**（标题、要点、来源、公式、图表），把**呈现方式**全部留给模板。

落到具体判断上，问题不是「要不要用模板」，而是三件事：这份产物的哪些部分会反复出现、哪些字段必须保留语义、模型有没有能力把内容正确归类到这些语义槽里。第三件事最容易被跳过，也最容易在长文档上翻车。

## 分工换来的是可修改性

回到开头那条线。Format Tax 的结论是「推理和排版拆开」，代价主要在提示词一侧；When Agents Go Quiet 的结论是延迟渲染省 48–72% 的 token 并消灭静默失败；SeaSlides 的结论是让模板拥有布局、样式和渲染，模型只写结构化内容。三份 2026 年的工作从三个方向指向同一个分界。

这个分界最终买到的东西不是「更快」，而是**修改落在正确的位置**。想换标题就改标题字段，想改间距就改渲染规则，两者互不牵连。反过来，如果格式和内容长在同一次生成里，改一个间距就要重跑一次「想内容」，而每重跑一次，内容的判断力都要再交一次税。

需要写清楚的边界有两层。Format Tax 明说了**多数近期闭源权重模型几乎没有格式税**，所以「直接让模型输出成品」在某些模型上确实可行，这一条判据不适用于那些模型——但延迟渲染的 token 与静默失败数据是在 Claude 3.5 Sonnet、GPT-4o、Llama 3.1 70B 上取得的，那是 2026 年 4 月的模型集合，不代表当前水平。SeaSlides 的结论也带范围限定：**四个生成模型中有三个、跨两种后端**，rich-content 宏平均最高，整体定性表现只是「有竞争力」。也就是说，语义抽象在富内容上优势更明显，不是在所有维度上全胜。

反过来，当一份产物本身就是原创视觉或特殊叙事——它的呈现方式就是内容的一部分——把渲染全部拿走才是错的。这条线该画在「呈现方式是否承载内容」，而不是画在「格式是否容易出错」。
