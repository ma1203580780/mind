把一段长对话压成一页摘要，最先消失的往往不是数字或结论，而是那个「不」字。2024 年有一项工作专门把「否定」拎出来单测（[arXiv:2406.05494](https://arxiv.org/abs/2406.05494)）：让 LLaMA-2-chat、Vicuna-v1.5、Orca-2 处理四类带 not 的输入，平均幻觉率分别是 **63.77%**（假前提补全）、**72.33%**（受限事实生成）、**36.6%**（多选问答）、**62.59%**（事实生成）。

第二层数字更麻烦。同一时期，FaithBench（[arXiv:2410.13210](https://arxiv.org/abs/2410.13210)）用专家标注比对 12 个幻觉检测器，最高的一项平衡准确率是 **57.65%**，最高的 F1-Macro 是 **54.90%**。

一边是模型在否定上系统性写错，一边是检测手段在同一个区域里接近抛硬币。所以「摘要丢了一个否定」不是一种靠复查就能兜住的疏忽。下面顺着这条线走三层：否定为什么会错，评测为什么看不见它，以及为什么这件事不能靠「压缩得更聪明」解决。

## 01 / 否定是模型的系统性盲区

论文把否定拆成四个任务，每一个都要求模型真的处理那个 not，而不是绕过去：假前提补全（把常识用 not 反转，比如「土星不是太阳系第二大行星」，模型要指出前提本身是错的）、受限事实生成（关键词里带 not，要组成一句正确的话）、多选问答（选出「没有」举办过冬奥会的国家）、事实生成（写一句含否定且为真的话）。

| 任务 | 做法 | 三个 13B 模型的平均幻觉率 |
| --- | --- | --- |
| 假前提补全 FPC | 常识被 not 反转，模型须指出前提错误 | 63.77% |
| 受限事实生成 CFG | 关键词含 not，须组成正确事实 | 72.33% |
| 多选问答 MCQA | 选出「没有」满足条件的选项 | 36.6% |
| 事实生成 FG | 写一句含否定且为真的话 | 62.59% |

在假前提补全上论文给了逐模型的结果：判对的比例是 LLaMA-2 46.67%、Orca-2 40.00%、Vicuna-v1.5 22.00%。反过来说，Vicuna 有 58.67% 的回答直接踩进了那个被否定掉的前提。

**为什么会朝这个方向错。** 论文给了一条线索：人类日常表达里肯定句远多于否定句，因此含否定的文本在训练与微调数据里占比更低。语言模型在压缩时天然向「更常见、更通顺」的表述漂移——而一句丢掉了「不」的话，恰好比原句更常见、更通顺。这不是随机噪声，是有方向的偏差：从「先不要发布」到「发布」，从「应该是网络问题」到「确认是网络问题」。漂移的落点总是那个默认的、肯定的、更像结论的版本。

论文还测了四种补救办法，结果把这件事从「不够小心」推成了结构问题。给模型喂检索到的相关知识时，幻觉不是减少而是增加（原文的说法是：coerces it to hallucinate even more instead of mitigation）；自我修正能缓解一部分，但在有些情况下会「通过引入幻觉信息把输出改错」。也就是说，「多给资料」和「让它再检查一遍」都不是修复路径。

这也不止发生在专门构造的题目上。一项跨语言跨时代摘要研究（[arXiv:2306.12916](https://arxiv.org/abs/2306.12916)）做了对抗测试：把原文句子改成与模型先验相反的版本，GPT-3.5 的摘要准确率在「情节遗漏」上是 0.67、「实体替换」是 0.71，而「情节否定」只有 **0.53**。三类里最低的一类，正是把一个事实翻成它的反面。

## 02 / 评测看不见它，因为它的坐标里没有约束

如果模型会丢否定，那「生成完再用评测器查一遍」听起来是合理的兜底。三个公开基准说明这条路是堵死的。

FaithBench 的结论最直接。它收录了 10 个现代 LLM（8 个模型家族）在困难样本上的摘要幻觉，由专家做逐片段标注，然后拿 12 个检测器来打分。摘要里的原话是：即使最好的检测器，在 FaithBench 上也「只有接近 50% 的准确率」。逐项看更清楚——最高的平衡准确率是 GPT-4-Turbo zero-shot 的 57.65%，最好的 F1-Macro 是 MiniCheck-Deberta-L 的 54.90%，Vectara 自家的 HHEM-2.1 是 55.68%（F1 40.86%）。为什么会这样，论文自己解释了：这些样本之所以被选进来，正是因为主流检测器在它们上面互不一致。检测器能达成共识的地方，本来就不需要人工标注；不能达成共识的地方，它的判断力就接近猜。

TofuEval（[arXiv:2402.13249](https://arxiv.org/abs/2402.13249)，NAACL 2024）把它推到了真实任务上：1479 份 LLM 生成的话题聚焦对话摘要、3966 个句子，由专业语言标注员逐句判定。结果是，**GPT-3.5-Turbo 生成的摘要有 22.2% 在整篇层面与原文不一致（主话题，MediaSum）**，Vicuna-7B 是 42.7%；五个模型在次要话题上的平均不一致率是 46.0%（MediaSum）与 43.6%（MeetingBank）。让模型自己当裁判更差：GPT-4 判断整篇主话题摘要是否一致，平衡准确率 63.7%，而一个「永远猜同一类」的基线是 50.0%。

第三份证据直接对着否定下手。一篇长文档摘要的压力测试（[arXiv:2511.07689](https://arxiv.org/abs/2511.07689)）把摘要改写成**逻辑等价的否定形式**——意思完全不变，只换极性的表达方式——然后看六个事实一致性指标会不会漂移。每一个都漂：MiniCheck「处理不好逻辑等价的否定」；SummaC-Conv 与 SummaC-ZS 在 SQuALITY 和 LexAbSumm 上明显受否定改写影响，论文的措辞是「说明它们不是完全不变量」；UniEval 则「在所有数据集上一致地无法处理逻辑等价的否定摘要，说明它缺少对逻辑形式的敏感性」；AlignScore 在否定与压缩上出现大幅掉分。

这不是评测器做得不够好，而是**它们量的维度里没有「约束」**。基于蕴含（NLI）的一致性指标问的是「这句话能不能从原文推出来」。把「不要发布」改写成等价说法，蕴含关系几乎不变，两者在这个坐标系里几乎重合。而一条约束的真正内容从来不是蕴含关系，是**它排除了哪些动作**。「先不要发布」和「发布」的字面距离是两个 token，在蕴含层面的距离也小得可怜，但它们的后果是相反的。

TofuEval 的误差分类表恰好把这一点命名了出来：它的八类误差里有三类叫 Tense/Aspect/Modality Error、Nuanced Meaning Shift Error、Contradiction Error，而「应该是网络问题」塌成「确认是网络问题」正落在第二类里。这类错误被标注系统承认存在，却处在自动检测器的分辨力之外。

## 03 / 两个极端都不成立

知道否定最容易被丢，直觉的解法是别压缩：把原文整段带上。这个方向同样是死的。

Chroma 在 2025 年 7 月的 Context Rot 报告（[research.trychroma.com](https://www.trychroma.com/research/context-rot)）评了 18 个模型，包括 GPT-4.1、Claude 4、Gemini 2.5 和 Qwen3。做法是把任务难度固定住、只改输入长度。LongMemEval 那组对比最直白：只给相关部分的「聚焦」输入平均约 300 token，完整输入约 113k token，而后者大部分内容与问题无关。报告的结论是：所有模型在聚焦输入上的表现都显著更好。NIAH 那组也一样——加一个干扰项就已经让表现低于基线，四个干扰项继续叠加恶化；甚至任务只是「照抄一串重复的词」，长度上去之后表现照样退化。

反方向也不成立，这次有官方说法。Anthropic 在 2025 年 9 月的上下文工程文章（[anthropic.com](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)）里写得很直接：压缩（compaction）的难点在于选择保留什么、丢掉什么，因为**「过度激进的压缩会导致那些细微但关键的上下文被丢失，而它们的重要性要到后来才显现」**。它给出的 Claude Code 做法不是「概括得漂亮」，而是一份固定保留清单：保留架构决策、未解决的 bug、实现细节，丢掉重复的工具输出。调参方向也给了：**先把召回拉满**，确保压缩提示词抓住轨迹里每一条相关信息，再迭代提高精确率。

把两端放在一起，问题的形状就出来了：上下文越长，模型对其中信息的召回越差——Chroma 测的 18 个模型里就包含 1M 上下文窗口的型号，退化照样出现；而压缩按定义是有损的。既然「全留着」和「压得更狠」都在掉分，剩下的唯一变量是**保留哪些**。

而这个取舍如果用通用摘要的标准来做，一定会先切掉否定和条件。它们的体量是一个「不」、一个「仅在……情况下」，出现频次低，还经常与「通顺的结论」方向相反。任何按「看起来重要」排序的压缩，都会把约束排在结论、实体和数字之后——不是因为算法差，而是因为在这套排序里，一个否定的字面权重确实接近于零。

那 63.77% 和 57.65% 真正指向的就是这件事：丢失约束不是一次疏忽，而是两个默认设置——模型的语义先验、压缩的取舍标准——共同作用的结果。

## 04 / 把约束从「可有可无」变成「必须有」

既然没有可用的自动检查，也没有「更小心」这种解法，能动的只剩产物本身：把约束从「摘要里有没有都行」改成「摘要必须有这个字段」。

这个判据不是从原则上来的，是从上面三层证据里推出来的。模型在最容易写反的地方就是否定与条件（第一层）；检测器在这个区域的分辨力只有 57.65% 与 63.7%（第二层）；长度和压缩率都不是能调的旋钮，长了会掉召回、短了会丢信息（第三层）。三层叠加之后，唯一还能固定住的东西是**信息类别**——哪些内容必须在，不随摘要长短变化。

Anthropic 的保留清单提供了一个可以照搬的形状：它固定下来的是三类判断依据（架构决策、未解决的 bug、实现细节），而不是三句结论。对应到任务交接摘要，要固定下来的是**读到之后动作会变**的那几类信息：禁止项（什么不能做）、适用边界（在什么范围内成立）、例外、未决项（什么还没定）、证据入口（去哪里核对）。它们的共同点不是「重要」——重要是相对的，会随摘要长度被稀释——而是「缺了它，下一步会走错」。

反过来，把「再检查一遍」当兜底是无效的。FaithBench 的 57.65% 和 TofuEval 的 63.7% 说明自动评测在这个区域没有可用的分辨力；假前提补全上 46.67%、40.00%、22.00% 的判对率说明，让模型自我修正也不是稳定解。能定的只有格式。

一份摘要省下来的空间，最终要由接手它的人来付。删掉一个「不」字会让摘变更短、更通顺、更像一份完成报告——这正是它危险的地方：损失不会以报错的形式出现，它会以一份写得更好的摘要的形式出现。所以衡量摘要的标准不是它压掉了多少，而是读完它之后，下一个动作有没有改变方向。那个「不」字不能丢，是因为它不是修饰，它是边界。

## 资料与边界

核对日期：2026-10-05。以下来源的数字均取自各自页面原文，逐字原句见交付报告。

- [Investigating and Addressing Hallucinations of LLMs in Tasks Involving Negation，arXiv:2406.05494](https://arxiv.org/abs/2406.05494)（2024-06-08）：四类否定任务的平均幻觉率 63.77%、72.33%、36.6%、62.59%；假前提补全判对率 46.67%（LLaMA-2）、40.00%（Orca-2）、22.00%（Vicuna-v1.5）；知识增强会把幻觉推高而非降低；自我修正有时会改错。三个模型均为 13B。
- [FaithBench，arXiv:2410.13210](https://arxiv.org/abs/2410.13210)（2024-10-17）：10 个 LLM、8 个模型家族、专家逐片段标注；12 个检测器中最高平衡准确率 57.65%（GPT-4-Turbo zero-shot）、最高 F1-Macro 54.90%（MiniCheck-Deberta-L）、HHEM-2.1 为 55.68%／40.86%；论文自述「即使最好的检测器也只有接近 50% 的准确率」。
- [TofuEval，arXiv:2402.13249](https://arxiv.org/abs/2402.13249)（NAACL 2024）：1479 份摘要、3966 句；GPT-3.5-Turbo 整篇不一致率 22.2%（MediaSum 主话题）、Vicuna-7B 42.7%；次要话题平均 46.0%／43.6%；GPT-4 整篇判断主话题的平衡准确率 63.7%，基线与 50.0%；误差分类含 Tense/Aspect/Modality Error、Nuanced Meaning Shift Error、Contradiction Error。
- [Stress Testing Factual Consistency Metrics for Long-Document Summarization，arXiv:2511.07689](https://arxiv.org/abs/2511.07689)（v1 2025-11-10，v2 2026-04-29；ACL 2026）：六个免参考事实一致性指标在七种保义扰动（含「逻辑等价的否定」）下评分漂移；MiniCheck 处理不好逻辑等价否定，SummaC-Conv/ZS 在 SQuALITY 与 LexAbSumm 上受否定改写影响，UniEval 在三个数据集上一致失败，AlignScore 在否定与压缩上大幅掉分。
- [Context Rot: How Increasing Input Tokens Impacts LLM Performance，Chroma](https://www.trychroma.com/research/context-rot)（2025-07-14）：18 个模型的评测；LongMemEval 聚焦输入约 300 token 对完整输入约 113k token，所有模型在聚焦输入上显著更好；单个干扰项就使表现低于基线，四个继续叠加；表现随输入长度一致退化。
- [Effective context engineering for AI agents，Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)（2025-09-29）：压缩过度会丢失「细微但关键、以后才显现」的上下文；Claude Code 固定保留架构决策、未解决的 bug、实现细节；建议先最大化召回再优化精确率。

时间与范围边界：以上实验集中在 2024 年 2 月至 2025 年 11 月，模型版本是各自论文当时选定的（FaithBench 用的是 2024 年的一批小尺寸模型，TofuEval 用的是 GPT-3.5-Turbo 与 Vicuna/WizardLM）。这些数字不代表 2026 年的模型水平；但它们描述的是**错误类型与评测盲区**，而不是某个模型的排行榜位置，类型不会因为版本更新自动消失。另外，FaithBench 只保留检测器互相不一致的困难样本，它的幻觉率与检测器准确率都只在困难样本上成立，不能外推到全量数据。

未采用的来源：Vectara Hallucination Leaderboard 与 Galileo Hallucination Index 属于第三方榜单，我只在第一手论文里读到对它们的引用，没有抓取其方法学说明，因此全文没有引用它们的排名。我也没找到直接测量「摘要中否定保留率」的公开研究；第一节改用否定任务的幻觉率与 CLCTS 的对抗准确率作为替代证据，这一点在正文表述中已经对应。
