同一次实验里有两个性质完全不同的失败。Claude-3-Haiku 在 GSM8K 上自由作答拿到 **86.51%**，改用 JSON 加 schema 约束后掉到 **23.44%**——但那一格的解析错误率是 **60.07%**，格式根本没守住。真正说明问题的是另一格：LLaMA-3-8B 做 Last Letter 任务，JSON 输出里只有 **0.148%** 的答案解析失败，格式几乎完美，分数却掉了 **38.15 个百分点**。

**格式合规和内容完好是两件事，而提示词能直接控制的只有第一件。** 下面从这条裂缝往回推：提示改的到底是什么，为什么它和后训练不在同一层，以及判断一个要求该落在哪一层的时候该问什么。

## 约束解码改的是可达 token 集合，不是做事的顺序

那篇 2024 年的研究把格式约束分成三档松紧（[arXiv:2408.02442](https://arxiv.org/abs/2408.02442)，v3 于 2024-10-14）：约束解码（JSON mode，生成时直接屏蔽掉不合语法的 token）、格式限制指令（在提示里要求 JSON/XML/YAML 并给 schema）、以及 NL-to-Format（先自由作答，再把答案转成目标格式）。同一批任务、五个模型、九种提示组合，逐档测下来。

结果不是单调的「格式越严越差」，而是分成两类任务、两个方向。推理任务上，约束越紧掉得越多；分类任务上，JSON mode 反而经常更好，论文的推测是它压掉了答案空间里的干扰项。具体到模型，差别极大：Gemini 1.5 Flash 的 GSM8K 从 **89.33** 到 **89.21**，几乎不动；GPT-3.5 Turbo 从 **75.99** 掉到 **49.25**；LLaMA-3-8B 从 **75.13** 掉到 **48.90**（同一张表，schema 约束一行）。

机制写得比我转述得更清楚。论文检查 GPT-3.5 Turbo 的 JSON mode 输出时发现：**100% 的响应把 `answer` 字段放在 `reason` 字段前面**，于是模型从「先想再答」变成了零样本直接作答。这一条把问题的位置钉住了——

约束解码作用在每一步的 token 分布上：它能把不合语法的 token 概率清零，但「先推理、再给答案」不是语法性质。schema 描述的是字段名、嵌套和类型，它管不住模型在填第一个字段之前有没有真的想过。于是格式被完整地满足了，推理链被静默地删掉了。Last Letter 那格是最干净的证据：解析错误率 0.148%，性能缺口 38.15 个百分点。反过来，LLaMA-3-8B 在 GSM8K 的 JSON 格式下解析错误率 22.75%，那是另一种失败，是格式没守住，不能算进「格式害了推理」这笔账里。两种失败要分开记。

NL-to-Format 这一档提供了对照：先让模型用自然语言作答，再做一次转换，多数模型上的性能与完全不加格式要求时几乎相同。**把格式从「生成时的约束」挪到「生成后的转换」，推理就回来了。**

## 提示和微调不是难度阶梯，受控比较里两者泛化相当

一个流传很广的说法是：微调容易学到伪相关、域外泛化差，所以提示更稳。这个说法在 2023 年的一次受控比较里没有站住（[arXiv:2305.16938](https://arxiv.org/abs/2305.16938)，v2 于 2023-05-30，Findings of ACL 2023）。作者指出，此前那些比较用的是**不同规模**的模型，于是「微调域外更差」这个结论到底是微调的固有性质，还是实验设置的局限，说不清。

他们把模型、样本数、参数量都控制住，规模从 **125M 到 30B** 扫过去，在挑战数据集上比 few-shot 微调和上下文学习。结论是：**微调过的语言模型在域外也能泛化得很好，两种方式的泛化程度相似**，差异由模型规模和样本数这类性质决定，鲁棒的任务适配本身仍然是个难题。

这条结论把「难的任务用微调、简单的用提示」这个顺序说法的地基抽掉了。区分两者的不是难度，而是**要求约束在什么对象上**：上下文学习改的是这一次的输入条件，微调改的是产出一个 token 时的默认分布。上一节的 JSON 实验正好是同一件事的另一面——同一个格式要求，写成 schema 进提示，是给这次采样加了一层条件；写进训练数据，才是把它变成模型的默认路径。

## 权重能改的是分布的形状：风格可以，事实性不行

如果说提示是「临时条件」，那后训练改的是什么？2023 年那篇关于模仿专有模型的论文给了一个很精确的回答（[arXiv:2305.15717](https://arxiv.org/abs/2305.15717)，v1 于 2023-05-25）。作者拿 **1.5B 到 13B** 的基座、**0.3M 到 150M token** 的 ChatGPT 输出做模仿微调，然后用众包评分和标准基准分别测。

两组评分给出了相反的结论。众包评分里，模仿模型的输出被评价为**与 ChatGPT 有竞争力**，指令遵循看起来好得多。但换成针对性的自动评测，在模仿数据没有大量覆盖的任务上，模仿模型**几乎没有缩小从基座到 ChatGPT 的差距**。论文的解释是：这些性能落差能逃过人工评分，是因为**模仿模型擅长模仿 ChatGPT 的风格，而不是它的事实性**。

**SFT 改的是输出分布的形状——风格、格式、措辞、拒答口径；它改不动能力上限。** 风格是分布层面的性质，所以它能被数据固定下来，一次训练之后每次都稳定；提示里的格式要求则每次都要重新条件化一次，这就是第一节那条 38 分的裂缝的来源。前面那条 NL-to-Format 的好成绩也印证了方向：把格式从生成过程里移出去，效果立刻回升。

同一层还有更硬的一类行为：拒答。2023 年 10 月的一篇红队研究（[arXiv:2310.03693](https://arxiv.org/abs/2310.03693)，v1 于 2023-10-05）报告，用**仅仅 10 条对抗设计的训练样本**、通过 OpenAI 的微调 API、花费**不到 0.20 美元**，就拆掉了 GPT-3.5 Turbo 的安全护栏，让它对几乎任何有害指令都响应。同一篇论文还发现，即使没有恶意，只用良性、常用的数据集做微调，也会在较小幅度上无意中损害安全对齐。作者的结论直白：模型初始的安全对齐再完美，也不保证在用户自定义微调之后仍然保持；现存的安全基础设施管的是推理时的行为限制，不覆盖微调。

拒答倾向就是这样一种权重属性。它不像格式那样能靠一段系统提示稳定压住，因为系统提示和它不在同一层——一个是每次调用时加的条件，另一个是产出一个 token 时的默认分布。反过来说，如果拒答口径对产品是硬要求，那它要么进训练数据，要么在推理之外加一层独立的检查，而不是写一条更严厉的提示。

## 回到那条裂缝：问两个问题

把「86.51 掉到 23.44」和「解析错误 0.148%、缺口 38.15 分」放在一起看，提示词与后训练的分工就不需要靠类比来记忆了。每个要求落下去之前，问两句。

**第一句：它约束的是这一次采样允许出现什么，还是模型默认会输出什么？** 前者是提示能做的事——schema、字段名、长度、示例。后者是权重的事——先推理再回答的顺序、风格、拒答口径、以及域外泛化能力。上一节的证据说明，把后一类要求硬塞进前一层，代价是它会被满足在字面上、丢在内容里。

**第二句：我用什么检查它？** 这一节的数字给出的答案是：检查必须落在内容上，而且要分开记两种失败。JSON 解析通过率是外形指标；解析通过而答案错，是另一类事故，它的数量级可以达到 38 个百分点；解析不通过（比如 LLaMA-3-8B 在 GSM8K 上 22.75%、Claude-3-Haiku 在 GSM8K 上 60.07%）才是格式事故。一张只看解析成功率的上线打点表，会把最贵的那类失败算成健康。

| 要求 | 提示层能做到什么 | 该落到哪一层 | 检查什么 |
| --- | --- | --- | --- |
| 输出可解析的 JSON/XML | 能做，但会挤掉推理 | 提示 + 一次格式转换（NL-to-Format） | 解析成功率与内容正确率分开记 |
| 先推理、再给答案 | 不稳定（GPT-3.5 Turbo JSON mode 100% 反例） | 训练数据里的示范顺序 | 字段顺序、中间步骤是否非空 |
| 输出风格、措辞、口径 | 每次重新条件化，漂移 | SFT 把它变成默认分布 | 抽样人工评，不看单次 |
| 拒答等安全倾向 | 系统提示只是一次条件 | 训练 + 推理之外的独立检查 | 定向红队，改措辞复测 |

回到开头那一格：Claude-3-Haiku 的 86.51 到 23.44，主要是格式没守住；LLaMA-3-8B 的 0.148% 与 38.15 分，才是格式守住了而行为没守住。**提示词和后训练不是同一件事的两种做法，它们改的对象不同，所以既不能相互替代，也不能相互补救。** 分清外形合规和行为合规，比争论该用提示还是该用微调有用得多。

## 资料与边界

核对日期：2026-10-05。以下数字均取自各论文的 arXiv `abs` 页或对应版本的 HTML 正文，未使用镜像站。这几项实验都集中在 2023–2024 年，模型与接口均已迭代，数字代表当时的水平。

- [Let Me Speak Freely? A Study on the Impact of Format Restrictions on Performance of Large Language Models，arXiv:2408.02442](https://arxiv.org/abs/2408.02442)（v3，2024-10-14；数据取自 [HTML 正文 v3](https://arxiv.org/html/2408.02442v3)）：GSM8K 上 Claude-3-Haiku 86.51 → 23.44、GPT-3.5 Turbo 75.99 → 49.25、LLaMA-3-8B 75.13 → 48.90、Gemini 1.5 Flash 89.33 → 89.21（表 1，加 schema 约束一行，准确率）；GPT-3.5 Turbo JSON mode 100% 把 answer 放在 reason 前；Last Letter 任务 LLaMA-3-8B JSON 解析错误率 0.148% 而性能缺口 38.15%；GSM8K 解析错误率 LLaMA-3-8B 22.75%、Claude-3-Haiku 60.07%（表 3）；NL-to-Format 与自然语言作答「几乎相同」的表述取自 4.1 节正文。
- [Few-shot Fine-tuning vs. In-context Learning: A Fair Comparison and Evaluation，arXiv:2305.16938](https://arxiv.org/abs/2305.16938)（v2，2023-05-30，Findings of ACL 2023）：控制模型、样本数与参数量（125M–30B）后，「fine-tuned language models can in fact generalize well out-of-domain」「both approaches generalize similarly」，取自摘要。
- [The False Promise of Imitating Proprietary LLMs，arXiv:2305.15717](https://arxiv.org/abs/2305.15717)（v1，2023-05-25）：基座 1.5B–13B、模仿数据 0.3M–150M token；众包评分认为输出与 ChatGPT 有竞争力，但自动评测显示「close little to none of the gap」，原因是「adept at mimicking ChatGPT's style but not its factuality」，均取自摘要。
- [Fine-tuning Aligned Language Models Compromises Safety, Even When Users Do Not Intend To!，arXiv:2310.03693](https://arxiv.org/abs/2310.03693)（v1，2023-10-05）：10 条对抗样本、成本不到 0.20 美元，通过 OpenAI API 微调即可让 GPT-3.5 Turbo 响应几乎任何有害指令；良性常用数据集也会在较小幅度上损害安全对齐。取自摘要。
